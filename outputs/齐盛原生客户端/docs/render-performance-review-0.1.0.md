# 原生 0.1.0 渲染开销只读复查

日期：2026-10-18。本次没有启动额外长测，没有修改 main、campus_streamer、client_settings 或线上设置。依据实际源码、209份本机导出glTF及协调者的既有跨端短测。约18.6ms的墙钟P95和1320次draw是已观察现象，不把它们直接等同单一GPU根因。

## 确定事实

1. client_settings.gd 的自动档在桌面固定为3D比例1.0、2xMSAA；main.gd按档位开启阴影。_automatic_left没有执行路径，尚无自动档的迟滞降级和恢复。高清／超清现在使用完全相同的渲染参数。
2. 战斗准备185个 combatOccluder 是当前完整遮挡的准备需求。max_resident=40只淘汰不再wanted的块，不是40块硬上限；不能称其已经把整个场景限制在40块，也不能为降低数字而删必要建筑。
3. campus_streamer._process在已就绪后仍每帧扫描wanted、尝试_pump、统计loaded、淘汰扫描／排序。main每帧另调用update_camera_visibility，对全部驻留块重新解析bounds数组、建立Vector3并转换视点；相机不变时也会重复。
4. 所有209块保留静态结构，导出已经做dedup/flatten/join兼容不透明网格。只读统计为1347节点、1336网格、2000 primitive、1995份材质描述；其中131份BLEND、548份doubleSided。纹理引用521项但图像哈希仅36种。将材质中的纹理索引解析为真实全局图像URI和采样器后，有288种完整材质描述、1707份重复描述。此数不是运行中Material RID数量，也不能据此声称合并后一定减少同样多draw。
5. main._frames持续收集并pop_front但未消费；它不是主要已证实瓶颈，却是可清理的无效热路径。
6. tests/native_crossplay_driver.gd每渲染帧同步读取controls文件并JSON解析；每250ms复制／排序全部frames和corrections、序列化和写报告。十分钟数据随时间增长，该诊断本身会扰动帧耗时。帧测量是进程回调间墙钟，包含限帧等待、其他进程竞争和诊断IO，不是GPU时间。

## 最小修改顺序

### 先减小测试扰动

- 以20至30Hz检查控制文件，其他帧沿用已解析的控制意图；保持实际60Hz输入采样和30Hz发送不变。一次性动作serial仍只执行一次。
- 进度回执不反复复制排序全部历史，只在末尾计算最终分位数；中间可用有界样本或较低频统计。把诊断自身耗时单列。
- 一并记录Godot实际process/physics耗时及可用GPU帧指标，再决定CPU还是GPU优先；保留现有墙钟指标用于玩家可感知停顿。

### 再清理不改变画面的热路径

- 当wanted修订、pending和碰撞状态均未变化且complete时，跳过重复泵送与loaded计数；到新视点／待办完成时再计算。不能只比较wanted数量。
- 淘汰检查降到低频；预先缓存每块bounds的中心和半径。相机变换或FOV确实变化才重算可见性，不改变保守的必要遮挡集。
- 删除未使用_frames或让其仅在受限诊断启用时采集；人物骨骼索引可在实例准备时缓存。

### 自动画质与阴影做短对照后实施

- 自动档按连续有效游玩帧的趋势分级降低分辨率、MSAA和阴影装饰；排除准备、后台、重同步和单次网络长帧，使用不同降低／恢复阈值与冷却期。手动档不悄悄覆盖。
- 先在同路线单变量比较阴影开关与MSAA，而非同时改三项后猜测归因；保留全部墙体、楼板、植被必要遮挡和实体。阴影不会参与服务器命中裁决，但降低画质仍须确认可读性。
- 明确高清与超清的实际参数；没有实现差异时不承诺两个不同效果。

### 材质／网格后续

先测实际材质RID重复和渲染状态切换，再考虑按完整纹理、采样、透明、双面和渲染状态建立静态共享缓存。不建议本轮全地图跨块合并；那会扩大包围范围、破坏分块淘汰及透明排序，并可能增加实际三角形工作。

## 没有据此提出的变更

不删公平性遮挡、不放宽敌情过滤、不降物理频率、不改地图原件；没有收益证据不新增另一套资源框架或更换渲染后端。安卓暂无真机，不能把4070桌面样本外推为安卓质量。

## 随后新增的独立策略模块

`src/render_profile.gd`新增纯视觉策略，尚待会话所有者接入主流程。`configure(quality,mobile,cap)`保持无关设置重放时的自动档状态；`profile()`提供实际scale/MSAA/shadows；`observe_frame(work_ms,eligible,elapsed_ms)`区分工作成本与累计时间。持续过载三秒降低一级、持续空余十二秒恢复一级，每次八秒冷却；单次大于100ms及未就绪／后台样本被排除。手动档不会被覆盖。高清2x与超清4xMSAA有明确差异，自动手机起点降低装饰成本。

`tests/native_render_profile.gd`以合成时间输入验证12项状态转换，通过约0.35秒headless检查；这是策略逻辑证据，不是实测FPS收益。实际接入口径须排除VSync、限帧等待和QA IO，不能将TIME_PROCESS误当纯CPU/GPU成本。上述“确定事实”为只读审查时点，不覆盖随后由会话所有者接入的修补。
