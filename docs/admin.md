# 管理后台

入口为 https://game.tianhw.top/admin，使用独立管理员账号；玩家账号无法登录后台。owner 管理管理员权限、审计和私密找回申诉。普通管理员按领域授权：feedback、publish、ranking、players、player-accounts、rooms、stats、operations。新增 player-accounts 不自动授予原管理员；“账号与权限”管理后台管理员，“玩家账号”管理游戏玩家。

原有工作台、反馈、议题、版本、玩法通知、成绩审核、玩家、房间、访问故障、管理员权限与审计继续使用。0.8.0 增加玩家账号详情与筛选、负责人找回申诉、服务状态；房间补操作回执，访问与故障补版本／玩法／设备筛选和趋势图。

0.8.3增加“小齐助手”：默认关闭，拥有者保存模型配置及密钥、测试两次调用，再启用。其他管理员需明确授予assistant权限，只能管理开关和额度、读取聚合用量；接口、模型、密钥和连接测试由拥有者管理。完整规则见[助手维护](assistant.md)。不显示玩家聊天正文，不记录密钥。

玩家账号可查看升级状态、竞技统计和成就来源，调整参榜限制、停用账号、隐藏公开档案、撤销会话或按来源重算。操作需原因与修订校验并写入具名审计；不改变比赛分数、不手动授予成就。隐藏档案不删除私人记录，停用会撤销登录会话。

玩家的战绩同步开关只控制单人突围／大飞的本局记录；关闭不抹去已有历史，重算不补回关闭期间的单人记录。联机私人战绩与成就始终记录，公开参榜仍由各自发布选择及资格决定。

负责人处理申诉时先核验独立归属证据，再明确填写玩家ID。默认可以拒绝证据不足的申诉；同名或短编号不能自动认领。批准生成24小时一次性重置凭证，仅数据库哈希及提交者私密回执查询可用，后台响应与审计不输出原始凭证。处理状态和修订防止重复批准覆盖。

服务状态为只读：显示实际目标、当前发行、三工作进程健康响应、房间心跳与已有性能数据。房间模拟更新时间不是完整周期或公网延迟；内存是工作进程RSS，不能按房间求和。健康接口与历史部署复检分别标注时间，不把旧复检当作现在的健康保证。

房间指令提交只代表排队。0.9.3起显示等待、执行中、已执行、无需执行、失败或过期；工作进程须校验代次、修订和成员再执行，排队超过60秒不再执行。执行后未收到回执会明确显示结果未确认，管理员应先刷新房间再决定是否重试。旧版本历史记录不补写成已执行。关闭房间会中断比赛，部署维护只停止新开局，玩法开关与部署维护独立。

版本说明与部署证据分开；编辑公开说明不会使版本上线。统计复用脱敏日汇总，不收集IP或完整UA；“估计会话”“页面访问”“在线人数”含义不同。反馈原文、截图、诊断和内部备注保持私密，公开议题只发布审核后的摘要。

## 0.9.3 实时运营

- 房间默认查看当前状态；关闭记录及长期失联记录进入历史分页。30秒未取得心跳显示未知并停止管理操作，两分钟后归入历史范围。后台可见时每五秒刷新，隐藏时停止；失败保留上次数据及时间。
- 已连接、断线保留席位和总容量分别显示。成员统一使用`playerId`；对玩家操作会核对当前成员，移出保留席位也会撤销其重连预留。已关闭房间只读，结算中的活跃房间可解散。
- 当前在线统计只接受游戏网页／原生的前台心跳：每30秒、90秒失效。活跃账号按账号去重，游客和客户端会话是连接口径，不能当作独立人数。主站访问仍单独记录。管理员只看到汇总，具名成员仍限房间权限。
- 会话令牌为服务器生成的临时随机值，只在内存中保留哈希与必要计数状态；不记录页面路径、IP、完整UA、聊天和世界坐标。上限20000条，过期回收。API重启后90秒显示统计恢复中。
- 分钟汇总保留24小时、每日峰值保留365天，不保存会话或账号明细。房间及操作元数据仅清理30天以前的关闭记录和已完成／过期指令，保留审计、比赛、成绩与复核证据。
- 新增`POST /api/v1/presence`，请求`{sessionId?,client:'web'|'native',active:boolean}`；响应临时`sessionId`及30／90秒参数。前台恢复立即发送，后台／离场发送`active:false`；客户端不得阻塞玩法等待统计。`GET /admin/presence`需stats权限，房间及操作结果需rooms权限。
- 数据库增加独立运行状态、操作结果和聚合表，仍保持schema6兼容读取。新指令在旧表标记已接收，实际执行只通过带代次的新版领取流程，避免旧工作进程在滚动升级或回退时误执行。回滚应用不恢复旧数据库。
