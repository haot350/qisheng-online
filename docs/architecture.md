# 架构与单一来源

游戏 `outputs/校园逃生游戏` 是 React／Three 客户端；主站 `outputs/校园交互网站/site` 是静态校园介绍与浏览。API `outputs/校园排行榜服务` 为 Fastify／SQLite，承载玩家账号、成绩、反馈、统计和独立 React 管理后台。实时服务 `outputs/校园联机服务` 为三工作进程权威模拟，经同源 `/realtime/w1` 至 `w3` 提供联机；浏览器不能自行提交合作或对战分数。

`outputs/校园共享模块` 是规则、弹药、排行、协议、运营类型、账号／成就目录和社区界面的规范来源。纯入口不引入 React、Three、DOM 或 WebGL；浏览器入口单独命名。消费者安装发行随附的 vendor tarball，后端不依赖开发目录链接。共享包版本与公开应用版本由发行流程处理，不能凭README自行重命名历史来源。

校园模型、碰撞、导航及地图资源保留来源编号、内容哈希与清单绑定。地图、协议和实时程序必须作为同一发行检查；公开哈希资源不可变，清单和索引短缓存／no-store。模型历史资产不可因软件版本升级而重写。

0.8.0 联机协议为 `campus-mp-0.8.0`，阻止旧账号客户端继续使用已退役的注册／联机入口；模拟、竞技规则与地图沿用各自清单来源，不因协议标识升级改写来源版本。

0.8.2新增私有输入确认范围、明确取消和输入时间轴代次；严重失同步通过input-rebase握手原子恢复检查点。预测只裁掉已应用／明确取消的命令，不以模拟步单独当确认。动态碰撞回放只用当前获准实体的有限历史，隐藏立即清除。校正证据仅有界内存保存本人输入和时长，不成为公开日志；新协议campus-mp-0.8.2与旧客户端不混用，玩法和计分不变。

菜单由MenuNavigation和MenuPage统一管理，返回按当前会话回根，不使用浏览历史栈。FPSVitals／FPSAmmo供单人与联机适配，静态WeaponLoadout使用当前玩法真实参数；正式图卡由原枪模离线生成并独立保存，不随公开源码上传。

0.8.3由SessionMenuActions承载局中工具入口，准备、大厅和暂停不显示公共侧栏。AssistantSession复用SessionOperations控制取消和迟到回答；独立懒加载聊天页面不引入游戏引擎。小齐后端与三个实时工作进程分离，参考[维护说明](assistant.md)。

本轮保留GameAPI兼容接口和既有ModeCapabilities，不全面改造引擎调用。已修补中等长帧的固定步预算、批量动态姿态恢复、精确遮挡缓存、实体快照字段比较及阴影释放。能力接口完整拆分和全局寻路预算作为后续项目，不能把本轮定向修改写成全引擎重构完成。

0.8.0 的账号与统计位于 API `accounts.ts`、`account-profile.ts`、`achievements.ts`。管理员接口分别位于 `admin.ts`、`admin-player-accounts.ts`、`admin-workbench.ts`；管理员账号与玩家账号各有权限和会话边界。账号表关联原 player_id，升级不复制身份；成就来源关联有效单人或权威多人结果，可从来源重建，状态撤回会撤销不再满足的成就。

数据库、配置、截图附件及备份独立于发行。应用回滚保留持久数据，跨 schema 回滚必须验证兼容；不能把放宽数据库 guard 当作通用策略。当前工作状态及真正发布版本见 [交接快照](HANDOFF.md)，0.6.7 等历史结构说明保持原样。

## 0.8.4渲染与表现边界

共享render-profile只决定画质策略，游戏render-quality应用到各自渲染器；操作偏好不选择素材画质。联机combat-gpu-preparer负责入场GPU准备，死亡材质／掉落随有界池所有权释放。观察在RAF处理，移动和射击仍固定步与服务器裁判；建筑视点门禁不会因网络恢复而放宽。制作名单为独立无WebGL懒加载页面，音频随active和visibility停止。正式发行默认服务器ZIP，--pages为可选旧兼容导出，不取消运行时资源预算。
